# 案例研究：用 APWA 跑完一篇信用风险实证论文

这套系统最初是为一次课程项目做的：既要设计一个多阶段 Agent 系统，又要用它完成一篇完整的实证研究。系统与论文是同一次工作的两面 —— 系统是方法，论文是验证。

之所以选信用风险评分作为验证场景，是因为它每一环都能被独立验收：数据口径对不对、标签怎么定义、基线强不强、概率校准得好不好、阈值对应的业务收益是多少。正好可以用来看这套编排在真实长流程里到底撑不撑得住。

## 三轮迭代

| 轮次 | 做了什么 | 系统承担的部分 |
| --- | --- | --- |
| 第 1 轮 | 数据下载与清洗、违约标签定义、逻辑回归 baseline、KS / ROC-AUC / PR-AUC、策略曲线 | 建立各阶段的产物契约（Skill 06→07→08→09） |
| 第 2 轮 | 换 FT-Transformer，对比树模型与深度模型 | 断点续跑，直接复用第 1 轮的数据产物 |
| 第 3 轮 | 自监督预训练（Denoising Autoencoder）+ 5 个模型横向对比 | 前两轮状态续上，只重跑 07 之后的阶段 |

三轮下来最实际的收益不是"更快"，而是**没有一次是从头重来**。第 3 轮改实验设计时，前面清洗好的数据和定义好的标签原样复用，`checkpoint_decision` 只把 07 之后标成 `rerun`。

## 第 3 轮结果

数据：5,000 条抽样样本 × 31 个特征，违约率 8.82%。

| 模型 | AUC-ROC | PR-AUC | KS | Brier | Precision | Recall |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Logistic Regression | 0.8281 | 0.4042 | 0.5325 | 0.1499 | 0.2534 | 0.7121 |
| XGBoost | 0.7659 | 0.2909 | 0.4182 | 0.0961 | 0.2819 | 0.3182 |
| MLP（随机初始化） | **0.8371** | 0.4179 | 0.5262 | 0.0643 | 0.6316 | 0.1818 |
| DAE + XGBoost | 0.7996 | 0.3689 | 0.4870 | 0.0779 | 0.3922 | 0.3030 |
| DAE + MLP | 0.8363 | 0.4084 | **0.5388** | 0.0652 | 0.5536 | 0.2348 |

预训练配置：编码器 5000→128→64→32→16，高斯噪声比例 0.15，重建 MSE 0.0807。

## 结论，包括不好看的

- **自监督预训练对 MLP 几乎没有提升**：AUC 0.8371 → 0.8363，基本持平；只有 KS 从 0.5262 提到 0.5388。花了十倍训练时间换来这个差值，不划算。
- **对 XGBoost 反而有效**：0.7659 → 0.7996。树模型在低维表格数据上本来就不吃表征学习，这里提升更可能来自特征增维带来的正则效应，而不是"预训练学到了更好的表征"——这个解释我并没有验证。
- **逻辑回归依然是强基线**：KS 0.5325，接近最好的 MLP。在样本量只有几千、特征维度三十几的情况下，复杂模型没有明显优势。
- **样本量太小**，8.82% 的违约率下测试集正例有限，AUC 差两个点在统计上不一定显著。这些结论不能外推到 Lending Club 全量数据。

这段是这套系统帮不上的地方：**判断"这个提升是否可信"必须人来拍板**。系统能把实验跑完、把表生成好，但它不会告诉你"这个提升看起来像噪声"。

## 系统做了什么，没做什么

| | 做了什么 |
| --- | --- |
| 系统 | 编排 14 个阶段的执行顺序、维护每阶段产物的契约、断点续跑、把论文/代码/图表/引用核验打包成交付物 |
| 人 | 定研究问题、决定换什么模型、判断结果是否可信、决定哪些结论能写、哪些必须标为局限 |

这个边界是刻意留的。把"判断"也交给模型，产出会看起来很顺，但你没法为它负责。
